> 都写在这里，答辩时按此口径说明，避免把仿真结果说成实测。

## 1. 真实数据 vs 仿真数据

| 内容 | 性质 | 来源/生成方式 | 存放位置 |
|---|---|---|---|
| 30 m DEM | **真实** | Copernicus DEM GLO-30（ESA），AWS Open Data 镜像 | `../数据集存储/Copernicus_DEM_GLO30/raw/` |
| 道路、水系、林地 | **真实** | OpenStreetMap，Overpass API 按 bbox 抽取，ODbL | `../数据集存储/OpenStreetMap/raw/` |
| 5 m 规划 DEM | 真实数据的重采样 | 30 m DEM 双线性重采样到 5 m，UTM 48N | `data/scenes/*/dem.tif` |
| 地块边界、田埂 | **仿真** | 沿局部等高线方向人工布设矩形地块，固定种子 | `fields.geojson/.shp` |
| 建筑、树木、电线 | **仿真**（道路/林地为真实 OSM） | 村庄/树丛/电线按规则布设，缓冲成硬障碍 | `obstacles.geojson/*.shp` |
| 病害风险值 | **仿真** | 低海拔 + 近村庄 + 平滑噪声，按分位数分三级 | `scene.json` 的 `risk/risk_level` |

| 航迹、覆盖率、能耗 | **仿真计算** | A* + 覆盖几何 + 一阶能耗模型 | `result/` |

> 场景 `scene.json` 的 `sources` 与 `notes` 字段也逐项标注了上述区分。

## 3. 处理流程（30 m → 5 m）

```
GLO-30 瓦片（EPSG:4326，1″）
  │ ① 按场景中心/尺寸计算 UTM 48N 范围
  │ ② rasterio.reproject 双线性重采样到 5 m（EPSG:32648）
  ▼
5 m DEM（dem.tif / grid.npz）
  │ ③ np.gradient 计算坡度、坡向、粗糙度
  │ ④ OSM 道路/水系/林地投影到局部坐标并栅格化
  │ ⑤ 人工布设建筑、树木、电线（固定种子）
  │ ⑥ 沿等高线布设地块，避开道路/建筑/陡坡
  │ ⑦ 风险值、起降点、障碍距离场
  ▼
scene_*/：GeoTIFF + GeoJSON + Shapefile + scene.json + preview.png
```

关键点：

- **没有修改真实地形**：5 m DEM 只是重采样，没有为了“像梯田”去雕刻地形；
- 地块与障碍物是叠加在真实地形上的矢量/栅格，独立可关；
- 30 m DEM 表达不了 5–15 m 宽的田埂，因此不声称“复刻了真实梯田地块”，
  只声称“在真实地形上构造了可复现的梯田仿真场景”。

## 4. 地块编号与风险

- 编号：`T001…T0NN`，每个场景独立；生成顺序即编号顺序（基线的固定顺序）。
- 地块属性：

| 字段 | 类型 | 说明 |
|---|---|---|
| `field_id` | string | `T001` |
| `risk` | float 0–1 | 仿真病害风险 |
| `risk_level` | `low/medium/high` | 按风险分位数切分（<0.40 / <0.68 / ≥0.68） |
| `priority` | 1/2/3 | 与风险等级对应，供路径排序 |
| `area_m2` | float | 多边形面积 |
| `mean_elev` | float | 地块平均高程 |
| `centroid` | [x,y] | 局部坐标质心 |

风险生成规则（仿真，不是模型预测）：

$$
r=\text{rank}\left(0.55(1-\tilde z)+0.25e^{-d_{\text{village}}/180}+0.20\,\eta\right)
$$

其中 $\tilde z$ 为地块平均高程在场景内的归一化值，$d_{\text{village}}$ 为到最近建筑的距离，
$\eta$ 为固定种子噪声；最后按秩归一化到 0.12–0.95，保证三档都有样本。

## 5. 坐标、时间与文件格式

- **局部坐标**：原点为场景西南角，x 向东、y 向北，单位 m。算法、JSON、网页均用此坐标。
- **地理坐标**：GeoTIFF/Shapefile 使用 **EPSG:32648**（WGS84 / UTM 48N）。
  `scene.json.origin_xy` 是场景西南角的 UTM 坐标，可用于把局部坐标转回 UTM。
- **时间**：ISO 8601，`+08:00`；巡检起点固定 `2026-10-01T08:00:00+08:00`，
  每张照片时间 = 起点 + 航迹时间 `t`。
- **栅格**：`grid.npz` 是算法缓存（比逐个读 tif 快），字段与 tif 一一对应；
  `field_id.tif` 中 0 表示非地块，1…N 对应 `T00N`。
- **矢量**：GeoJSON 用局部坐标（0..size），方便网页；Shapefile 用 UTM 绝对坐标，方便 QGIS。
  两者属性字段一致。

## 7. 局限与合规

1. 30 m DEM 的平面精度约 ±30 m、高程精度数米级，不能支撑厘米级避障；
2. 地块、建筑、树木、电线为仿真，**不得**用于真实飞行或真实农田面积统计；
3. OSM 数据可能存在缺漏/偏移，尤其山区小路与建筑；
4. 巡检照片是占位图，**不是**真实田间图像，不能用于训练病害模型；
5. 使用本数据发表成果时，请注明 Copernicus DEM 与 © OpenStreetMap contributors（ODbL）。
