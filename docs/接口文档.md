# 接口文档（成员A → 成员B / 成员C / 网页）

版本：1.0（对应 `schema_version: "1.0"`）
所有坐标：**场景局部平面，原点西南角，x 向东、y 向北，单位 m**；GeoTIFF 为 EPSG:32648。
所有时间：ISO 8601，带 `+08:00`。

---

## 1. 航迹 JSON（A → 网页 / B）

文件：`result/traj/{scene}_{method}.json`，`method ∈ {baseline, improved}`。

| 字段 | 类型 | 说明 |
|---|---|---|
| `schema_version` | string | `"1.0"` |
| `scene` / `scene_name` | string | 场景 ID / 中文名 |
| `method` | string | `baseline` / `improved` |
| `created_at` | string | 生成时间 |
| `coords` | object | `crs=EPSG:32648`、`local_origin_xy`、`utm_origin_xy`、`unit=m` |
| `uav` | object | 速度、高度、FOV、幅面半径、GSD、电池 |
| `route` | string[] | 地块访问顺序，如 `["T004","T012",...]` |
| `fields` | object[] | 逐地块：`field_id/risk/risk_level/priority/visit_order/entry/exit/n_strips/variant/coverage_pct` |
| `waypoints` | object[] | 航迹点，见下表 |
| `metrics` | object | 指标，见下表 |

### 1.1 waypoint

```json
{
  "seq": 12,
  "x": 345.67, "y": 512.34, "z": 1578.9,
  "t": 183.4,
  "heading": 87.5,
  "field_id": "T007",
  "action": "capture"
}
```

`action` 取值：

| 值 | 含义 |
|---|---|
| `takeoff` | 起飞（首点） |
| `transit` | 转场 |
| `capture` | 到达拍照点（有 `field_id`） |
| `replan_start` | 重规划起点（仅重规划航迹） |
| `land` | 降落（末点） |

`heading`：0=北，90=东（罗盘角）。

### 1.2 metrics

| 字段 | 单位 | 说明 |
|---|---|---|
| `path_length_m` | m | 水平航程 |
| `flight_time_s` | s | 含爬升/悬停/起降 |
| `energy_wh` | Wh | 一阶能耗模型 |
| `battery_pct_used` | % | 占 300 Wh 比例 |
| `battery_reserve_ok` | bool | 是否满足 15% 余量 |
| `planning_time_s` | s | 规划耗时 |
| `n_waypoints` / `n_images` | int | 航迹点/拍照数 |
| `high_risk_mean_order` | float | 高风险地块平均访问次序（越小越早） |
| `weighted_latency_s` | s | 风险加权完成时间 |
| `min_clearance_m` / `mean_clearance_m` | m | 转场段与障碍的最小/平均距离 |
| `near_obstacle_length_m` | m | 距障碍 <8 m 的航段长度（诊断用） |
| `safety_violation_m` | m | 距障碍 <3 m 的航段长度 |
| `collision_count` | int | 穿越硬障碍的采样点数（应为 0） |
| `coverage_pct` | % | 由 03 回填；02 刚跑完为 `null` |

## 2. 巡检结果 JSON（A → B）

文件：`result/inspect/{scene}_{method}_inspection.json`。

| 字段 | 说明 |
|---|---|
| `visit_order` | 地块访问顺序 |
| `fields[]` | `field_id/risk/risk_level/visit_order/area_m2/covered_m2/coverage_pct/n_images` |
| `totals` | `n_fields/n_images/coverage_pct/mean_field_coverage_pct/covered_area_m2/field_area_m2` |
| `images[]` | 图像索引（见下） |
| `coverage_grid` | 覆盖栅格元数据（`coverage.tif` 与 `dem.tif` 对齐） |

### 2.1 图像索引（给成员B）

```json
{
  "image_id": "scene_medium_improved_0007",
  "field_id": "T007",
  "timestamp": "2026-10-01T08:04:12+08:00",
  "waypoint_seq": 34,
  "x": 345.67, "y": 512.34, "z": 1578.9,
  "heading": 87.5,
  "gsd_cm": 0.29,
  "path": "images/scene_medium/improved/T007_003.jpg",
  "simulated": true,
  "note": "仿真占位图，非真实田间照片；成员B可用真实/渲染图替换同名字段"
}
```

B 直接读 `images[]`，按 `field_id + timestamp` 关联即可；图片是占位图（128×128，
带 `SIMULATED` 水印），**不要**用于训练病害识别模型，替换为真实/渲染图后再训练。

## 4. HTTP API（FastAPI）

启动：`python scripts/06_serve_api.py` → `http://127.0.0.1:8000`。
交互文档：`/docs`（Swagger UI）。所有接口只读本地 JSON/CSV，无数据库。

| 方法 | 路径 | 返回 |
|---|---|---|
| GET | `/api/scenes` | 场景列表 + 每场景基线/改进指标 |
| GET | `/api/scene/{sid}` | 场景元数据、地块 GeoJSON、障碍 GeoJSON、底图 URL |
| GET | `/api/traj/{sid}/{method}` | 航迹 JSON（第 1 节） |
| GET | `/api/inspect/{sid}/{method}` | 巡检 JSON（第 2 节） |
| GET | `/api/metrics` | `metrics.csv` 的 JSON 数组 |
| GET | `/api/replan` | 三场景重规划结果 |
| GET | `/basemaps/basemap_{sid}.png` | 地形晕渲底图 |
| GET | `/` | Leaflet 地图页面 |

### 4.1 `/api/scene/{sid}` 示例

```json
{
  "scene_id": "scene_medium",
  "name": "中等场景·多依树密集梯田",
  "size_m": 900,
  "bounds": [[0,0],[900,900]],
  "basemap_url": "/basemaps/basemap_scene_medium.png",
  "fields": {"type":"FeatureCollection","features":[
    {"type":"Feature","geometry":{"type":"Polygon","coordinates":[[[x,y],...]]},
     "properties":{"field_id":"T001","risk":0.82,"risk_level":"high","priority":3,"area_m2":683.2,"mean_elev":1570.9}}
  ]},
  "obstacles": {"type":"FeatureCollection","features":[...]},
  "depot_xy": [875.0, 690.0],
  "counts": {"n_fields":22, ...}
}
```

### 4.2 curl 示例

```bash
curl http://127.0.0.1:8000/api/scenes
curl http://127.0.0.1:8000/api/traj/scene_medium/improved
curl http://127.0.0.1:8000/api/inspect/scene_medium/improved
```

## 5. 给 C 的风险反馈接口（预留）

C 输出高风险地块后，A 可读取如下 JSON（当前未自动接入，字段与任务书一致）：

```json
{
  "field_id": "T007",
  "timestamp": "2026-10-01T11:00:00+08:00",
  "risk_level": "high",
  "predicted_risk": 0.91,
  "inspection_priority": 1
}
```

接入点：`src/planner/route.py::order_improved` 可按 `inspection_priority` 覆盖 `priority`，
再重跑 02–04 即可完成 C→A 闭环。当前实验中的风险值来自场景 `scene.json`（仿真），
用于演示闭环逻辑，不代表 C 的预测结果。

## 6. 版本与兼容

- `schema_version` 变更时，轨迹/巡检 JSON 同步升级；
- 字段只增不改，新增字段默认 `null`；
- 地块编号、坐标原点、时间格式属于团队约定，变更需三人同步（见任务书第七章）。
