## 1．项目现在研究什么

建议项目名称：**面向加榜梯田的气象—地形协同农业风险监测与无人机巡检决策系统**。

第一阶段选取贵州加榜梯田中加车村附近的梯田群作为实验对象，重点研究：在山地高差、零碎田块和灌排条件共同影响下，怎样发现值得关注的农业环境异常，并把这些异常转化为无人机巡检任务。

可将水稻梯田作为第一阶段工作假设，具体作物、品种、生育期及灌溉制度仍需通过现场或当地农业资料确认。此前较宽泛的病害预测、变量作业目标可以保留为后续扩展，但第一版先完成“环境信号—巡检建议—图像核查”的闭环。

一句话说明：**先判断什么时候值得去看，再根据地形、田块和影像判断重点看哪里，最后由无人机取得证据。**

| 调整项 | 加榜梯田方案 |
|---|---|

| 首批风险关注点 | 强降雨后的灌排和田埂核查、持续少雨下的供水状况、持续湿润环境下的作物异常观察 |

## 4．三条适合梯田场景的分析主线

### 主线 A：强降雨后的灌排与田埂巡检

先计算近期 1、3、7 日降水。出现值得关注的降水事件时，结合上游汇水范围、进出水口、沟渠连通、历史堵塞或损坏记录，筛选巡检对象。无人机重点查看排水口、田埂冲刷、异常积水或作物倒伏迹象。

**稻田正常蓄水不等于内涝。**积水是否异常取决于生育期、管理水位、持续时间及作物受淹情况，不能只凭照片中的水面或降雨量判断。地形坡度本身也不能直接推断哪块梯田会被淹。

输出示例仅作为字段表达：“近期累计降水达到所设规则，田块位于已核实的汇水通道下游，建议核查排水口。”没有灌排资料时，应输出“区域降雨事件，具体田块待核查”，不能虚构地块级结论。

### 主线 B：持续少雨下的梯田供水状况

结合近 7、14、30 日降水、持续少雨天数、温度与土壤水分变化，筛选可能需要查看供水状况的时段。再结合灌溉水源、沟渠通水记录和实测水位，判断哪些田块需要巡检。

ERA5-Land 土壤体积含水率代表模式网格的土壤状态，**不等于梯田蓄水深度，也不等于水稻根区可利用水量**。不应把某个含水率数值直接翻译成“这块田缺水”。

### 主线 C：持续湿润环境下的作物异常巡检

使用湿度、温度和连续降雨作为环境背景，结合影像中的颜色、纹理或长势异常，安排人工或近距离核查。若后续选定稻瘟病等具体病害，应补充适宜温度、叶面湿润持续时间、品种、生育期和病害标签等资料，再建立并验证模型。

日平均相对湿度不能替代叶面湿润时长；气象条件有利也不代表已经发病。第一版结果命名为“湿润环境关注时段”或“待核查作物异常”，避免用没有证据的确诊名称。

低温、高温等可以作为第二批指标，具体阈值应随目标作物、生育期和地方资料确定。不要直接照搬保定方案中的气象阈值、物候日期或风险权重。

## 5．气象怎样与地形、影像连接

推荐流程：

```text
区域气象背景 → 候选事件日期
                    ↓
真实田块 + 地形/灌排信息 + 影像或现场异常
                    ↓
田块巡检建议（理由明确，未知项保留）
                    ↓
B同学安排观测点、地形跟随路线及多机任务
                    ↓
采集图像 → 人工/算法核查 → 更新记录与规则
```

NASA POWER 和 ERA5-Land 网格尺度比当前初始框还大或相近，CHIRPS 的 0.05°网格在当地也约为数公里。因此，本次使用 **一个背景请求点 J01** 获取 NASA 和 ERA5 数据，另下载初始框的 CHIRPS 网格。不再把一个小实验区人为布成9个“独立气象观测点”。

实际下载核验：CHIRPS服务在这个初始框中仅选中1个有效格点，其余3个数组位置为固定空间掩膜。表中的CHIRPS统计因此等于该格点值，不能称为整个矩形的精确面积平均。ERA5逐小时数据共43824条，合并日表覆盖2021—2025年的1826天，核心变量未发现时间缺测。

有一组背景天气，并不妨碍田块巡检优先级不同；差异必须来自实际田块信息。例如，同一天降雨背景相同，已核实存在排水堵塞记录的田块与没有该记录的田块，可以有不同核查顺序。若这些信息尚未取得，就先输出区域事件，等待补齐，不能用插值伪造梯田级气象细节。

与 B 同学的接口应区分两类地形：30 m DEM 可以支持山体地形、相对高程和粗尺度汇水分析，但通常不能解析窄田埂、单级梯田台面和小沟渠。将30 m数据插值到5 m只会变密，不会产生真实5 m细节。用人工构造的田埂和障碍物做仿真时，需明确标成模拟几何，并与实测数据分开。

梯田台面可能接近平坦，而其所在山坡很陡，不能用粗DEM坡度直接当作田面坡度。B 同学还应区分相对地面高度与海拔高度；你的历史2米风速只能作环境背景，实时飞行决策仍需要作业现场及飞行高度条件。

## 6．建议采用的输出字段

| 字段 | 含义 |
|---|---|
| `event_date` | 候选事件对应日期 |
| `data_end_date` | 用到的数据最新覆盖日期，避免把旧数据当作实时状态 |
| `event_type` | 持续少雨、集中降雨、持续湿润等，名称与规则对应 |
| `indicator_values` | 实际计算的指标值及单位 |
| `rule_version` | 阈值和判断逻辑的版本及依据 |
| `spatial_support` | 区域格点背景／已核实田块资料／影像证据等 |
| `plot_id` | 真实田块编号；尚无边界时为空 |
| `terrain_or_drainage_evidence` | 地形或灌排方面的具体依据，不把猜测写成实测 |
| `inspection_topic` | 建议看什么，例如排水口、田埂、供水情况 |
| `priority_reason` | 为什么优先；第一版可按明确规则排序，暂不使用无依据的加权总分 |
| `evidence_status` | 仅气象提示／已有图像线索／已人工核查 |
| `missing_inputs` | 缺少的田块、作物、生育期、灌排或现场信息 |

保留两个概念：C 同学提出“巡检需求与理由”，B 同学依据电量、地形、起降条件等生成“可执行任务”。风险重要性与路线可行性都要满足，不能由气象模块单独给出实飞许可。

## 7．你下一步按什么顺序做

**第一步：跑通已有数据。**打开加榜版Excel，确认与保定文件不同；运行包内指标脚本，查看7/14/30日降水及土壤湿度变化，先不套未经核准的灾害阈值。

**第二步：与同学统一空间底图。**核对截图坐标系，确认真实梯田边界。向 B 同学要田块编号、地形来源、坡面与田面区分、灌排资料可信度；向影像同学要图像日期、地理位置和人工核查记录。

**第三步：选一种事件做最小实验。**建议先做降雨事件后的灌排与田埂核查，流程比较容易展示。挑选历史降雨较多的时段，只称为“候选事件”，再寻找对应记录或图像支持，不虚构灾情。

**第四步：实现可解释规则。**一条规则对应一个指标、一个出处、一个适用条件。阈值先由地方资料或训练集制定；没有依据时只展示指标大小和历史排序，不宣称有经过验证的风险等级。

**第五步：做闭环演示。**地图点击田块后展示背景气象、真实地形/灌排依据和巡检建议，交给路线模块，最后展示巡检图像或明确标注的仿真结果。

**第六步：设计验证。**若有真实标签，可按时间划分，例如2021—2023年制定规则、2024年调整、2025年留作测试；计算百分位、归一化和阈值只能使用当时已知数据，避免未来信息泄漏。五年样本较短，极端事件可能很少，需报告样本数和不确定性。没有标签时，报告数据质量、流程可行性和案例，不报告病害预测准确率。

可比较的实验：仅使用气象背景生成任务 vs. 加入经过验证的地形/灌排与影像依据生成任务。评估任务是否找到更多经确认的异常、巡检时间和里程、无效巡检比例。不得将人为规则生成的标签作为“真实灾害”再验证同一规则。
